## Rationale

A claim whose first run is all `assertion_failed` at base and all `passed` at head is confirmed with one more run in the same worktree. The confirmation covers only those ids. A witness whose second outcome differs makes the claim `unstable`. The verdict result is `fail` when any claim failed, `unstable` when some claim is `unstable` and none failed, and `pass` otherwise. The process exits 0 only for `pass`. A first run that already fails the claim stays `fail` and is not rerun.

## Counter-argument

Leaving flake as pass or fail keeps verdict to one run per revision. One confirmation still misses a test that fails one time in three, and every claim that would otherwise pass pays for a second run.
