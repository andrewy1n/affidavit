## Rationale

A manifest committed with the code makes the verdict a pure function of the repo and a revision. Base and head claims are a `git diff`, so an oracle hash change without an approval is mechanical to detect. It removes the dependency on adaptive-artifacts, so any orchestrator (including GSD) can use it, and changes are reviewable in a pull request. Run logs and reports are not committed; they go to a log sink, and the orchestration client may mirror verdicts into its own store.

## Counter-argument

Keeping claims and oracles as adaptive-artifacts records reuses what exists: record revision tamper detection, the dashboard, and the views. The executor can edit a committed manifest as easily as code, so approvals still need a source outside the agent (signed commits or the dashboard), and on one machine neither is airtight.
