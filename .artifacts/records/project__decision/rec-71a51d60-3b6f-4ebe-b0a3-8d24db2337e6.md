## Rationale

The remaining trust and audit phases already have directions in their bodies. Settling them together lets plan and execute run without a re-discuss between landings. Pre-approving plan-review only when the plan matches this slate keeps the human out of the loop without blank-check planning.

## Counter-argument

Planning every phase before any code lands would surface the full task graph once. That also freezes plans that early landings may invalidate, so the autopilot path re-plans each phase from the settled approach instead.
