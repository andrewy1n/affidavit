## Rationale

The owner chose a signed amendment entry in the committed manifest. `claims-authority` already makes the verdict a function of the repo and a revision, so the approval has to be in that tree. The executor can edit the manifest the same way it edits code. A signature checked against the allowlist at `--base` is the part it cannot produce: a key added in the same revision cannot authorize the amendment, and an unsigned hash change fails the verdict.

## Counter-argument

A dashboard approval is the better human surface. The owner already uses the dashboard for Needs-you gates, and a click is easier than holding a signing key out of the agent session. On one machine an unlocked ssh-agent makes a signature no stronger than a click, and a dashboard gate would record the approval without a new file format.
