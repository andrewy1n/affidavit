## Rationale

Earning a claim must be an explicit act a later agent can query without mistaking every technique run for acceptance. A separate `project:evidence-binding` keeps observations append-only and lets bind, unbind, and recheck be verbs with clear subjects. Patching `claim_ids` on the observation would reuse the trail type as a mutable ledger and blur mention with earn.

## Counter-argument

Patching observation `claim_ids` via supersede needs no new record type and fewer verbs. That saves contract surface, but it makes the trail mutable and trains agents to treat “listed under this claim” as already accepted — the failure mode this phase exists to prevent.
