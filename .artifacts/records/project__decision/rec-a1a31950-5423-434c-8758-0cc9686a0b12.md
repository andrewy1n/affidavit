## Rationale

The name, the history, and the `affidavit/` package (check, close, oracle red, suite) already are the evidence layer. Moving the skills, dashboard, and session scripts out to a new repo means this repo's tests can prove it works with no orchestration present, and a second client can use it the same way the skills do.

## Counter-argument

A separate package inside this repo (own pyproject and CLI, no imports from skills or the dashboard) gets the same boundary without a second repo, a second store, cross-repo version pinning, or moving the dashboard's history. The boundary could be extracted later once the `aff` verbs stop changing.
