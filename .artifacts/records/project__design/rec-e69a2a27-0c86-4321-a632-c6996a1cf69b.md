## Architecture

1. Define a canonical attestation document (commit SHA, base/at as needed, manifest hash, runner digest, claim results) and sign it with namespace `affidavit-verdict`.
2. CLI (or subcommands of `aff`) emit and verify; verify loads allowed_signers the same way amendments do.
3. Ship a GitHub Action (or workflow) that checks out a fixture, runs verdict, signs, and uploads/verifies the attestation.
4. Tests mint keys like amendment tests and cover tamper and bind mismatch.

## Interfaces

- Emit: stdin/argv → attestation file or stdout
- Verify: attestation + expected commit/manifest → exit 0/1
- Payload fields locked at plan-phase to match R1

## Decisions

- `verdict-attestation`: SSH canonical payload; not Sigstore; not unsigned-local-only.

## Invariants

- Bad signature or wrong bind ⇒ non-zero verify.
- Distinct signing namespace from amendments.

## Assumptions

- frozen-environment has landed runner digest (or this phase digests runner argv the same way).

## Tradeoffs

- Deploy-key ops vs Sigstore simplicity.
- Local agents can still print unsigned JSON; gates that require verify are what close the hole.

## Risks

- Key distribution in real CI. Mitigation: fixture action first; document allowlist update.
