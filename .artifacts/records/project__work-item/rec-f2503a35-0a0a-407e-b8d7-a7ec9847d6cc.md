## Description

R1: `aff audit --base --head` splits the diff into blocks, skips test and prose blocks, reverts each remaining block, reruns frozen claim tests through `run_tests`, and labels each block noticed, not noticed, or inconclusive.
R2: `aff audit` never reports a test-file block as a finding target.
R3: On the `check-runner` range used in spikes, the audit reports the unnoticed `build_batch(request, cwd=args.cwd)` block.

## Approach

1. Add `affidavit/audit.py`: split `git diff -U0 base head` into hunks, drop `.artifacts/**`, test files, and prose per decision `audit-interface`, and keep for each block the file, new-file start/end lines, and added text.
2. For each block, create a detached worktree at `head` (like `affidavit/verdict.py` does), reverse-apply that single hunk with `git apply -R`, run the claim tests with `affidavit.runner.run_tests` and the manifest runner, and label the block: `noticed` when any claim test that passed at head is `assertion_failed` after the revert, `not_noticed` when all still pass, `inconclusive` when the patch does not apply, errors dominate, or no claim test passes at head. Remove the worktrees after use.
3. Claim tests: union of the head manifest's claim tests (`affidavit.manifest.load_manifest`, absent manifest means none) and each `--test` id.
4. `affidavit/cli.py`: add `aff audit` printing the JSON object `{"advisory": true, "base", "head", "blocks": [...], "mutants": [], "survivors": []}`; exit 0, or 2 on usage or git errors.
5. The audit does not change `aff verdict`. Do not edit `tests/test_audit.py` (frozen oracle) or any existing test.
